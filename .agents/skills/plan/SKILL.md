# Plan

1. Inspect the relevant code, constraints, and recent issue/PR activity; search open and closed issues for prior work.
2. Define the problem, proposed approach, and testable acceptance criteria; include non-goals or open questions only when useful.
3. Keep one shippable change per issue, with phases as a checklist rather than placeholder sub-issues; a trivial fix needs no separate plan.
4. Present the plan in chat unless the user requests filing it; then reuse an existing issue where appropriate, respecting text ownership in `AGENTS.md`.
5. Ask before adding board structure or bulk issues; use an existing milestone if it fits rather than inventing ceremony.
6. Separate approval of the plan from approval to implement it; leave a concrete next action.

The issue body holds the current plan; comments hold progress, decisions, verification, and handoffs.

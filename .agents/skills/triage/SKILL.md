# Triage

1. Read the full set of open issues, their bodies and recent comments, and linked PRs; paginate API results rather than assuming the first page is complete.
2. Check candidate closures against code and merged PRs; age alone does not make an issue obsolete.
3. Propose keep/close/fold decisions with reasons and source-to-target links; preserve useful decisions and acceptance criteria.
4. Obtain approval for the specific changes before editing board state, closing issues, or creating milestones/labels.
5. Comment with the reason and surviving issue link before closing; preserve others' text and avoid closing work with an active PR.
6. Re-read the board and report what changed and what remains unresolved.

Close rather than delete so the history remains recoverable; a smaller issue count is not a substitute for accurate tracking.
